## What's broken / open

### 1. `compile-tcc-self` fails silently

- The test:
  `tcc -DONE_SOURCE=1 -I/src/tinycc -I/src/tinycc/build-stubs -I/src/userspace /src/tinycc/tcc.c -o /tmp/tcc-rebuilt.elf`
- Files staged correctly:
  - `vendor/tinycc/` → ISO at `/src/tinycc/` via the new block in
    `iso.sh:32–50` (uses `cp --parents`, filters by extension).
  - Verified locally: `isodir/src/tinycc/tcc.c`, `tcc.h`, `build-stubs/*.h`
    all present.
- Failure mode: `tcc` exits non-zero, no stderr appears in the serial log
  (`/tmp/iso-test.log`). Probably:
  - In-OS TCC running out of heap compiling its own ~1 MB ONE_SOURCE TU
    (kernel heap is limited; AST blows past it).
  - Or a missing libc symbol surfaced only when tcc.c is the input
    (none of the `-DCONFIG_*` defines from `build-tcc.sh` are passed
    here; the runtime path defaults differ — could cascade into an
    error path).
- Next steps to diagnose:
  1. Re-add `-DCONFIG_TCC_*` defines one at a time (start with
     `CONFIG_TCCDIR=/usr/lib/tcc` and `CONFIG_TCC_SYSINCLUDEPATHS`),
     see if the failure clears. Slice 1 plan documented the full list.
  2. Inspect heap usage: `cat /proc/meminfo` or similar before/after
     the compile; if heap is saturated, the path forward is to grow
     it or implement compaction.
  3. Try compiling a smaller TU first (e.g. a single `.c` file from
     vendor/tinycc/ with `tcc -c` only) to bisect whether the issue
     is the ONE_SOURCE size or something specific to tcc.c.

### 2. Pipes / redirects / list operators are untested end-to-end

- The implementation:
  - Kernel: `FD_KIND_PIPE`, `pipe_ring_t`, `SYS_PIPE=42`, `SYS_DUP2=63`
    in `src/kernel/include/kernel/fd.h`,
    `src/kernel/arch/i386/proc/fd.c`,
    `src/kernel/arch/i386/proc/syscall.c`,
    `src/kernel/include/kernel/syscall.h`.
  - Userspace: `sys_pipe`/`sys_dup2` stubs in
    `src/userspace/syscall.h`; pipeline runner +
    redirect extractor + list-operator walker
    + `wait` builtin + `jobs[]` in `src/userspace/sh.c`.
- Why no smoke test: `shell-smoke.sh` runs through the **kernel-side**
  sh interpreter (`sh_script.c`), which doesn't tokenize `|` / `&&`
  / `||` / `&` / `>` / `<` at all. All four features only exist in
  `/apps/sh.elf` (userspace).
- Validation paths available to the next operator:
  - Boot the ISO interactively (`./run.sh iso boot`), then type
    `echo hello | cat`, `echo X > /tmp/r.txt; cat /tmp/r.txt`,
    `true && echo yes`, `false || echo no`, `sleep 2 & wait`
    into the shell prompt (which is `/apps/sh.elf`).
  - Or add an HMP-driven scenario to `tests/ui_test.sh` that
    types these into the keyboard ring and greps serial. Pattern:
    look at existing scenarios in the file like
    `scenario_user_sigusr1_handler` for sendkey shape.

### 3. Slices 5 + 6 untouched

- **Slice 5 — Kernel self-rebuild ladder.** See plan file for the
  5a → 5e ladder (single .c→.o → `ar` applet → `tcc -ld` →
  `mkmakar.sh` driver → boot the result). Major risk: TCC's
  internal linker may need `makar.ld` simplified (no `KEEP()`,
  no glob `*(.text.*)`). Acceptable v1.0 carve-out: keep `boot.o`
  host-built at `/usr/lib/boot.o`, link the rest in-OS.
- **Slice 6 — In-OS Limine installer.** Limine binaries already
  ship on the ISO under `/limine/`. Build a
  `/apps/mkboot.elf` that writes `limine.conf` to FAT32 boot
  partition + `dd`s the 440-byte MBR bootstrap blob from
  `limine-hdd.bin` into LBA 0 of the target disk (preserving
  partition table at offsets 440–511). Lifted-and-shifted from
  the existing GRUB install path conceptually. `fdisk`/`cfdisk`
  are already shipped — they provide the partitioning primitives.

## Files changed in this session

### Slice 0
- `src/kernel/arch/i386/shell/sh_script.c` — added
  inline-if-with-`else` support (lines ~460–477), and made both
  inline + multi-line `then`-keyword detection word-boundary-aware
  (lines ~443–456 and ~518–531) so values containing the substring
  `then` (e.g. `ran-then`) no longer truncate the condition.
- `src/userspace/shell-smoke.sh` — dropped the "inline if
  misbehaves" warning; added two regression tests
  (`inline-if-else-then`, `inline-if-else-else`).

### Slice 1
- `src/userspace/tcc_compat.c` — `execvp` now does a real PATH
  walk (hardcoded `/apps:/bin` since envp isn't plumbed yet);
  if `file` contains `/` it skips the walk. Returns `-1` /
  `errno=ENOENT` if no candidate found.
- `src/userspace/libc-tcc.sh` — added the `compile-tcc-self`
  entry (currently failing — see open item #1).
- `iso.sh` — added vendor/tinycc/ source staging block (copies
  `.c`/`.h`/`.S`/`.def` into `isodir/src/tinycc/`).

### Slice 2 (pipes)
- `src/kernel/include/kernel/fd.h` — `FD_KIND_PIPE = 7`,
  `pipe_ring_t` struct with refcount_r/refcount_w, `pipe` +
  `pipe_is_writer` fields on `fd_entry_t`.
- `src/kernel/arch/i386/proc/fd.c` — `pipe_release` helper;
  `fd_table_clone` bumps the right end's refcount instead of
  copying; `fd_close` + `fd_table_destroy` release the right
  end and free the ring at refcount 0.
- `src/kernel/include/kernel/syscall.h` — `SYS_PIPE = 42`,
  `SYS_DUP2 = 63` (Linux i386 ABI).
- `src/kernel/arch/i386/proc/syscall.c` — `SYS_PIPE` + `SYS_DUP2`
  dispatcher cases; `FD_KIND_PIPE` branches in `SYS_READ`
  (spin-yield on empty, EOF when refcount_w drops to 0) and
  `SYS_WRITE` (spin-yield on full, `-EPIPE` when refcount_r is 0).
- `src/userspace/syscall.h` — `SYS_PIPE`/`SYS_DUP2` defines +
  `sys_pipe`/`sys_dup2` stubs.
- `src/userspace/sh.c` — `child_exec_external` (PATH walk with
  direct `execve`, no fork), `split_pipes`, `run_pipeline`,
  pipe detection in `run_one_segment`.

### Slice 3 (redirection)
- `src/userspace/sh.c` — `redirect_t` struct,
  `extract_redirects`, `apply_redirects`, pending-redirect
  state for `spawn()`, per-stage redirect application inside
  the pipeline child.

### Slice 4 (`&&` / `||` / `&`)
- `src/userspace/sh.c` — `run_one_segment` (the old `run_line`
  body), new `run_line` that scans for top-level `&&`/`||`/`&`
  and gates segment execution; `jobs[]` table; `wait` builtin
  in `run_builtin`.
